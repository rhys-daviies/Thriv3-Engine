# 2. Module structure

```
INITIAL_ELIGIBILITY_RESULT   5 states, no VERIFIED_ELIGIBLE
VERIFICATION_STATUS          VERIFIED | PARTIAL | UNVERIFIED
STALENESS                    CURRENT | STALE_AGE | STALE_CYCLE | STALE_SOURCE
SOURCE_STATUS                REACHABLE | UNREACHABLE | UNCHECKED
INITIAL_ELIGIBILITY_RULES    3 verified records (NCAA DI, DII, DIII)
UNVERIFIED_ASSOCIATIONS      NAIA, NJCAA, USCAA — named, with what is missing
ruleStaleness()              the three A7.32 triggers, no network access
assessInitialEligibility()   division + isInternational + asOf.  NO GPA, NO SAT, NO ACT.
initialEligibilityForAthlete()  the thin caller — reads `origin` and nothing else
```

**The strongest guarantee in the module is what it refuses to accept.** `assessInitialEligibility`
takes no GPA, no SAT and no ACT. There is nothing to misuse — a future reader who wants to read a
transcript GPA as a core-course GPA has to add the parameter in the open.

The header states the three-way distinction explicitly:
`INITIAL ELIGIBILITY != CONTINUING ELIGIBILITY != INSTITUTIONAL ADMISSIONS`.

# 3. Rule records encoded

Taken from `A7.32-eligibility-rules.md`, not reconstructed. Every record carries `source`,
`sourceSection`, `sourceUrl`, `sourceStatus`, `sourceCheckedAt`, `verifiedAt`, `effectiveFrom`,
`effectiveTo`, `verificationStatus`, `caveats` and `requires`.

| | NCAA DI | NCAA DII | NCAA DIII |
|---|---|---|---|
| core courses | 16 | 16 | — |
| distribution | 4/3/2/1/2/4 | **3/2/2/3/2/4** | — |
| core GPA | **2.300** | **2.200** | — |
| test required | **false** | **false** | — |

| national standard | yes | yes | **`false`** |
| `evaluable` | **false** | **false** | **true** |

**`evaluable: false` is the load-bearing field.** It says Thriv3 cannot assess the rule from data it
holds — **not** that the rule is doubtful. The rules are well sourced; the inputs are missing.

**`timingRule: null` for DII is deliberate and commented.** A search summary during A7.32 asserted
10/7 applies to Division II; the primary page does not say so. Inheriting it would have been exactly
the "DII = DI" assumption A7.32 was told to test rather than presume.

Caveats carried, not silently dropped: the DI academic-redshirt category and the DII partial-qualifier
category are both recorded as **NOT ESTABLISHED**.

# 4. Result semantics

| state | meaning | reachable now? |
|---|---|---|
| `NOT_APPLICABLE` | no governing-body standard applies | **yes** — DIII domestic only |
| `NOT_ESTABLISHED` | rule verified, Thriv3 lacks its inputs | **yes** — the common case |
| `REVIEW_REQUIRED` | evidence materially inconsistent with a verified standard | **no, by construction** |
| `NO_ISSUE_IDENTIFIED` | inputs present, none conflicting | **no, by construction** |
| `RULE_UNVERIFIED` | no verified rule, or the rule went stale | **yes** |

**There is no `VERIFIED_ELIGIBLE` state, in any spelling** — asserted by a test that rejects any
value matching `/ELIGIBLE/`. Thriv3 certifies eligibility for no association in any division, and
every result carries `thriv3Certifies: false` plus the real authority.

`NO_ISSUE_IDENTIFIED` is documented as describing **Thriv3's search, not the athlete's status**, and
is unreachable today because no rule has its inputs.

**`REVIEW_REQUIRED` was deliberately not wired up.** The only candidate inference — "overall GPA far
below the core-course threshold" — compares two different quantities, and §8 of the brief forbids
slipping it in unpreregistered. `NOT_ESTABLISHED` is preferred over false precision. A test asserts
the reachable set is exactly `{NOT_APPLICABLE, NOT_ESTABLISHED, RULE_UNVERIFIED}`.

# 5–11. Behaviour by association

| input | result | authority named |
|---|---|---|
| NCAA D1 domestic or international | `NOT_ESTABLISHED` | NCAA Eligibility Center |
| NCAA D2 domestic or international | `NOT_ESTABLISHED` | NCAA Eligibility Center |
| **NCAA D3 domestic** | **`NOT_APPLICABLE`** | The institution |
| **NCAA D3 international** | **`NOT_ESTABLISHED`** | NCAA Eligibility Center |
| NAIA | `RULE_UNVERIFIED` | NAIA Eligibility Center (PlayNAIA) |
| NJCAA | `RULE_UNVERIFIED` | — |
| USCAA | `RULE_UNVERIFIED` | — |
| unrecognised division, or `null` | `RULE_UNVERIFIED` | — |

**Division III is the only evaluable rule, and it is evaluable precisely because the answer is a
property of the division rather than of the athlete.** Its domestic reason string says in terms that
this is *"not a statement that the athlete is admitted or academically cleared"*.

**The DIII international path is the one A7.32 uncovered and A7.31 had not anticipated.** Returning
`NOT_APPLICABLE` there would be wrong: the Eligibility Center certifies DIII international athletes,
so the dimension applies and Thriv3 holds none of what that certification consumes.

**NAIA is `RULE_UNVERIFIED` despite A7.32 assembling a probable standard.** PARTIAL is not VERIFIED:
the bylaw page 404'd and two NAIA-controlled sources conflicted on one-of-three versus two-of-three.
The probable version stays in the register and out of the code. A test asserts no NAIA record exists
in the rule table.

**USCAA carries the naming hazard in its record** — that `uscaa.org` is the United States *Corporate*
Athletics Association — so nobody encodes payroll rules as collegiate eligibility. Asserted by test.

# 12. Staleness

Three triggers, evaluated in the order that makes the reason most useful to a maintainer:

1. **SOURCE** — `sourceStatus === UNREACHABLE` → `STALE_SOURCE`
2. **CYCLE** — past `effectiveTo`, or verified before the current academic year began (1 August, the
   boundary Proposal 2022-34 itself uses)
3. **AGE** — verified ≥ 12 months ago → `STALE_AGE`

**A stale rule degrades to `RULE_UNVERIFIED` and is not applied.** Tested on all three triggers,
including the dangerous case — **a stale Division III rule must stop returning `NOT_APPLICABLE`**,
because that is the one evaluable path and the one that could silently survive expiry.

*Silent application of an expired rule is how the removed NCAA sliding scale would still be in
production.* That sentence is in the module.

# 13. Source reachability architecture

**No network access at evaluation time.** `sourceStatus` and `sourceCheckedAt` are **stored
metadata**, set by a separate maintenance process; `ruleStaleness` consumes them and makes no
request. An eligibility assessment that depended on an HTTP call would be non-deterministic, slow,
and would fail open on a network blip — the worst possible failure mode for a caution signal.

The maintenance checker is **not built** in this phase. Its contract is the two fields.

# 14. `ncaa_eligibility_id` audit — and a defect found

**Intended semantics:** the athlete's NCAA Eligibility Center identifier — the key to the only
authority that can answer dimension B.

**Current state:** column exists (`server/db/migrate.js:26`), is in the player entity, is collected
by a free-text input (`src/components/PublicProfileFields.jsx:66`), is displayed in two places, and
is **`null` for all four athlete records**. Seed data carries one sample value.

> ## The defect
>
> **`server/export/renderProfile.js:101`**
> ```js
> if (present(athlete.ncaa_eligibility_id)) items.push('<span class="badge">NCAA ID verified</span>');
> ```
>
> **The public athlete profile — the page exported and sent to college coaches — claims the NCAA ID
> is VERIFIED purely because the field is non-empty.** There is no format check, no checksum, and no
> contact with any NCAA system. An athlete typing a single character earns the badge.
>
> This is the exact failure class this workstream exists to prevent — presence of data rendered as a
> verified status claim — and it is the first instance found that is **outward-facing to the people
> making recruiting decisions**. Flagged as a separate task; **not fixed here**, because A7.33
> forbids UI changes.

**Recommendations:**

1. **Relabel or remove the badge.** "NCAA ID on file" is true; "verified" is not.
2. **Validate format at entry** (numeric, typically ten digits) — but validation is not verification
   and must not restore the claim.
3. **Identifier only, for now.** It should not drive any eligibility result. Its value is that it is
   the handle a *future* official-status workflow would use.
4. **Storing the raw identifier is justified**, but it is a third-party identifier tied to a minor's
   academic record: it should not appear on a **public** profile at all. Recommend removing it from
   the public export and keeping it operator-side. That is a privacy judgement for the operator.
5. **Do not populate it artificially**, and do not build an NCAA integration.

`server/db/campaignSchema.test.js` · `server/db/sendMigration.test.js` ·
`server/routes/sendDurability.test.js`

**Recommendation: migrate, but not now and not as one change.** The migration itself is mechanical —
swap the path for `resolveFixtureDatabase({ root, requires })`. The risk is **not** mechanical: each
file must be told *which tables it actually needs*, and getting that list wrong converts a passing
suite into a silently skipping one, which is worse than the defect. Three of them
(`campaignSnapshot`, `reportDelivery`) only mention the path inside string fixtures for
path-traversal tests and **must not be touched at all**.

**Suggested phase: one file at a time, each verified to still RUN its assertions against a real
database** — the same proof used for the three repaired in A7.31. Low priority: the defect only
manifests in a worktree, and it now has a documented fix and a working helper.

# 20. Smallest next step

**Do not extend the rules. Close the NAIA gap instead.**

One person with the NAIA 2025-26 Official Handbook (p. 70, cited by NAIA's own interpretations site)
reads Article V, Section C, Item 2 and records the bylaw text. That single artifact converts NAIA
from `RULE_UNVERIFIED` to a fourth verified record, and NAIA is **193 men's programmes** — the
largest unverified block after NJCAA.

It is above any further engineering because every remaining engineering task is blocked on inputs or
rules that do not exist, and because the foundation is deliberately designed so that adding a
verified rule is a data change, not a code change.

**Explicitly not next:** wiring `REVIEW_REQUIRED`, collecting core-course transcripts, building an
NCAA integration, or connecting this module to matchmaking. It should stay inert until a dimension-B
surface is designed.
