## 2. Root cause — and it starts one step earlier than expected

The chain, verified from code and acquisition artifacts:

1. **`variants.py` synthesises `/roster/season/{YEAR}`** (lines 47 and 56) — it treats the calendar
   year as a season **identifier**.
2. **The site resolves that identifier to a different team entirely** and returns HTTP 200. Kansas
   State's canonical proves the segment is an opaque internal id, not a year: `season/1536` is a
   **2016** roster.
3. **`parse_nuxt` scans the entire payload** for player-shaped dicts — 5,028 entries at Grand Canyon
   — with **no scoping to the requested sport or team**.
4. `lib.position()` rejects `DIS`, `Distance`, `Jumps`, `Throws`, `MD` → blank.
5. Rows survive with blank positions and are written under the **requested** programme and sport.
6. `importRosterSheets.js` stores them faithfully as women's soccer.

**Earliest preventable point: step 2→3, before any player is read.** `parse_nuxt` already touches the
payload object carrying `displayTitle` — the object that *also* carries `players` — and uses it only
to scrape a year, discarding the sport.

## 15–17. Permanent upstream prevention specification

Written as executable code in **`shared/sportIdentity.js`** so the upstream task has something exact
to port. **`_roster_pipeline/lib.py` was not modified.**

`assessPageIdentity({ requestedSport, requestedSeason, observed })` → `{ sport, season, action }`.

**Before extracting any player**, inspect `<title>`, `rel="canonical"`, payload `displayTitle`, any
explicit payload sport/team field, and payload season. Then:

| condition | action |
|---|---|
| explicit **sport** contradiction | **REFUSE** — do not extract, do not write, raise review |
| explicit **season** contradiction | **REFUSE** — do not accept as the requested season |
| no identity signal | **REVIEW** — never manufacture agreement |
| agrees | EXTRACT |

**Sport and season are assessed independently.** A combined verdict would have passed Grand Canyon on
its correct year. **A page naming a foreign sport contradicts even if it also contains the wanted
word**, because the safe reading of an ambiguous page is not "yes".

### Why the check must be pre-extraction (§16)

The contaminated rosters had **valid names, valid class years, plausible row counts, and 100%
turnover** — which the season gate reads as a *healthy new roster*. The only signal that objected was
the position mapper refusing track events, and that is a coincidence of the sports involved: **two
soccer programmes swapped with each other would have produced perfect positions and shipped
silently.**

So: field completeness ≠ identity · row count ≠ identity · turnover ≠ identity · position vocabulary
≠ identity · name overlap ≠ identity. **Only the page can say which team it is.** The function takes
page identity only — the downstream signals are not parameters, so they cannot be substituted.

### Season identity (§17)

Kansas State is a first-class finding: **wrong sport AND wrong season**. Current validation would
**not** have caught the season error — the 2026 gate proves a roster is *new* by measuring turnover
against 2025, and a 2016 track roster is 100% "turned over", which reads as new. The missing rule is
the explicit one above: compare the page's own stated year against the requested year, and refuse a
contradiction. **The `/season/{YEAR}` URL form should also stop being synthesised**, since the segment
is an opaque id, not a year.
