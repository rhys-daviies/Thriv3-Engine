## Two distinct root causes, not one

### 1. The worktree stub became authoritative

`shared/academicMajors.test.js:19` and `shared/evidence/k3cRemediation.test.js:22` both did:

```js
const DB = path.join(ROOT, 'server/data/recruitmatch.sqlite');
const d = fs.existsSync(DB) ? describe : describe.skip;
```

**Both halves are wrong in a git worktree.** The path ignores `RECRUITMATCH_DB`, which is how every
other part of the codebase is told where the database is. And the gate asks whether a **file
exists**, not whether it **holds anything** — so the 741 KB worktree stub, which has **zero
`colleges` rows**, passed the gate. The suites then ran against an empty database and four
assertions failed because SMU, Adams State and the women's arrival rows were not there to find.

**Fix:** `shared/testing/fixtureDatabase.js`, which resolves in order

```
RECRUITMATCH_TEST_DB  ->  RECRUITMATCH_DB (when not ':memory:')  ->  repository default
```

and reports `usable: true` **only when every table the suite named actually contains rows**.

**Why a new variable rather than reusing `RECRUITMATCH_DB`.** `vitest.config.js` sets
`RECRUITMATCH_DB=':memory:'` for every worker deliberately, so that a suite opening the database
in-process can never touch the working one. That is correct and was **not** changed. It also means
that inside a worker `RECRUITMATCH_DB` answers "where must you not write", not "where is the data" —
so a third variable is needed for suites that drive a real command in a subprocess.

### 2. `describe.skip` does not skip the describe body

`server/lib/evidenceBaseline.test.js:367` computed a `probe('')` result **directly in a describe
callback**. `describe.skip` marks the *tests* skipped but still runs the *callback*, so
`fs.copyFileSync(DB, tmp)` executed even when the pinned dataset was absent and threw `ENOENT` at
collection — making the file report "no tests" rather than "skipped", which the file's own header
calls the one outcome worse than red.

**Fix:** made the probe lazy and memoised, so the subprocess still runs exactly once for the block.
The DB resolution in that file was already correct (a pinned baseline dataset, never the live
database) and was left alone.

# 1. The three-way academic semantic model

One signal has been answering three questions. They share the word "academic" and the word
"pre-read" and nothing else.

| | **A. Institutional admissions** | **B. Governing-body eligibility** | **C. Academic process** |
|---|---|---|---|
| **question** | will *this institution* admit *this athlete*? | may this athlete *compete* under the association's academic rules? | does this programme run a specific academic step regardless of the athlete? |
| **decided by** | an admissions office | NCAA / NAIA / NJCAA / USCAA | the institution or conference |
| **varies with** | athlete **and** institution | athlete **and** division — **not the institution** | institution/conference — **not the athlete** |
| **evidence held** | `sat_avg`, `admit_rate` (54.7% / 76.8% men's) | **none for initial eligibility** | **none** |
| **outputs** | NORMAL · VERIFY_EARLY · PRE_READ_BEFORE_RELIANCE · INSUFFICIENT_EVIDENCE | CLEAR · REVIEW_REQUIRED · **NOT_ESTABLISHED** | PROCESS_EXPECTED · NO_PROCESS_EVIDENCE · UNKNOWN |
| **today** | A7.27–A7.30 shadow, GATE 2 | **does not exist** | **does not exist** |

**Three properties that make the split non-negotiable:**

1. **B does not vary with the institution.** A 1.0 GPA fails NCAA D1 initial eligibility at Old
   Dominion and at Harvard identically. Any signal keyed on `admit_rate` is structurally incapable of
   carrying it.
2. **C does not vary with the athlete.** A routine pre-read applies to the strongest recruit on the
   roster. Any signal keyed on a shortfall is structurally incapable of carrying it.
3. **Only A varies with both**, which is exactly why it is the only one that has been modellable so
   far — and why it silently absorbed the other two.

**On the vocabulary collision:** "pre-read" names both *risk resolution* (A) and *routine procedure*
(C). The default naming should therefore not reuse it across dimensions — C's states are about a
**process**, not a **concern**, and **a process flag must never imply academic weakness.**

# 2. The Old Dominion decomposition

Real card, A7.30 `U-14`, women's NCAA D1:

| evidence | value |
|---|---|
| athlete | GPA **1.0**, SAT **400**, ability 9 |
| programme | enrolled SAT 1197, **acceptance 90%** |
| shortfall | **−797** |

| dimension | verdict | why |
|---|---|---|
| **A. Institutional admissions** | **NORMAL** | An institution admitting nine applicants in ten is not the obstacle. **This is correct and must not change.** |
| **B. Governing-body eligibility** | **NOT ESTABLISHED / REVIEW REQUIRED** | All three independent evaluators, unanimously and unprompted, cited the NCAA D1 core-GPA floor. No admissions office and no coach can waive it. |
| **C. Academic process** | UNKNOWN | no evidence |

**The two verdicts are simultaneously true and neither is wrong.** The shadow returned NORMAL and
was right about the question it asks; the independents returned PRE_READ and were right about the
question they were asked.

> **The boundary must NOT be modified to absorb this case.** Making the acceptance-rate rule fire at
> 90% acceptance to catch a 1.0 GPA would break the clearance that has produced the
> zero-over-escalation record across three phases, and would mis-fire on every other
> high-acceptance programme where the athlete is academically fine. It is a category error and the
> preregistration excludes U-14 from the frontier study for exactly this reason.

**The product consequence, which is the operative finding of this phase:** because dimension B does
not exist, **the absence of an admissions flag must never be rendered as academic clearance.**

| dimension | verdict |

programme until real evidence arrives (§8).

# 4–6. Responsibility boundaries

## A. Institutional admissions — owns, and only this

**Owns:** whether *this institution's* published admissions evidence, against *this athlete's*
record, warrants checking with the coach before the programme is treated as straightforwardly
recruitable.

**Does not own:** association eligibility, procedural requirements, admission prediction,
probability of any kind, or the claim that the athlete is academically fine.

**Evidence:** `sat_avg`, `admit_rate`, athlete SAT. Coverage 54.7% / 76.8% men's, 70.7% / 95.5%
women's, with NJCAA at 1/228 and 5/228.

## B. Governing-body eligibility — **not supported, and the audit is unambiguous**

**What the repository actually encodes.** `shared/eligibility.js` holds **continuing eligibility —
the eligibility *ceiling*** — as rules-as-data: how many further seasons a *current roster player*
may play. Per-rule `source` and operator verification date (2026-09-19), covering NCAA D1 (both the
2026 age-based model and the pre-2026 rule), D2, D3 and NAIA. **NJCAA and USCAA are named in
`UNRULED_DIVISIONS`** — nothing may be inferred for them.

**What it does not encode: initial eligibility.** A repository-wide search for core-course GPA,
sliding scale, initial eligibility, Eligibility Center, amateurism or qualifier-certification
returns **zero** hits outside unrelated uses of the word "qualifier".

| association | continuing eligibility | **initial eligibility** |
|---|---|---|
| NCAA D1 | ✓ encoded, sourced, dated | **absent** |
| NCAA D2 | ✓ | **absent** |
| NCAA D3 | ✓ | **absent** |
| NAIA | ✓ | **absent** |
| NJCAA | explicitly UNRULED | **absent** |
| USCAA | explicitly UNRULED | **absent** |

> **Verdict: ACADEMIC_ELIGIBILITY cannot be implemented in A7.31 and is not implemented.** The
> unanimous NCAA reasoning in A7.30 rests on rules Thriv3 does not hold. Encoding them from model
> recollection would be inventing rules, which the brief forbids and which `shared/eligibility.js`
> itself forbids in its header: *"A rule with no source is not a rule."*

**The architecture is already proven, though, and should be reused exactly**: rules as data, a
`source` and a verification date on every rule, `UNKNOWN` as a first-class model rather than a
fallback, and unruled associations named rather than guessed. What is missing is **external
verification of current initial-eligibility standards**, which is an operator task with an effective
date, not an engineering task.

## C. Academic process — data model definable, evidence zero

**Owns:** whether an institution or conference runs a specific academic step for recruited athletes,
**independently of the athlete**.

**Evidence held: none.** Not one programme carries a pre-read, banding or nomination fact.

**Cleanest semantics — and the naming matters.** `PROCESS_EXPECTED` / `NO_PROCESS_EVIDENCE` /
`UNKNOWN` is serviceable but invites being read as a concern scale. Preferred:

| state | meaning |
|---|---|
| `ACADEMIC_STEP_ON_FILE` | evidence exists that this programme runs a specific academic step |
| `NO_STEP_ON_FILE` | we hold evidence about this programme and it records no such step |
| `UNKNOWN` | we hold nothing — **today's value for every programme** |

`NO_STEP_ON_FILE` and `UNKNOWN` are deliberately distinct, and neither is a statement about the
athlete. **A process state must never contribute to a concern level in any dimension.**

# 9. Coach Recruiting Intelligence — academic process model (design only)

Three layers, distinguished structurally rather than by convention, because collapsing them is how
one coach's remark about one athlete becomes a standing claim about a university.

**1 · Institution-level policy** — a property of the institution, slowest-moving.

`institution_academic_policy`: `unitid` · `pre_read_available` · `pre_read_required_for_recruits` ·
`banding_process` (conference academic index / institutional band / none / unknown) ·
`nomination_required` · `source` · `source_url` · `observed_at` · `applies_to_cycle` ·
`evidence_state` (`STATED` / `REPORTED` / `UNKNOWN` — **never `INFERRED` from ingestion**)

**2 · Programme/coach practice** — what *this coach* actually does, which may differ from policy.

`programme_academic_practice`: `college_id` · `sport` · `season` · `typical_pre_read_timing` ·
`coach_gpa_guidance` · `coach_test_guidance` · `observed_supported_band` (with a count and date
range) · `source` · `observed_at` · `confidence`

**3 · Athlete-specific event** — a FACT about one pair, append-only, expires with the cycle.

`ACADEMIC_INFORMATION_REQUESTED` · `TRANSCRIPT_REQUESTED` · `TEST_SCORE_REQUESTED` ·
`COACH_SAYS_ACADEMICS_SUFFICIENT` · `COACH_SAYS_ACADEMICS_BORDERLINE` · `PRE_READ_REQUESTED` ·
`PRE_READ_SUBMITTED` · `PRE_READ_POSITIVE` · `PRE_READ_CONDITIONAL` · `PRE_READ_NEGATIVE` ·
`ADMITTED` · `DENIED`

**The loop:** layer-3 events at one programme aggregate into layer-2 `observed_supported_band` — the
recruited-athlete latitude figure that has been the load-bearing unknown since A7.26 and that §11
still forbids inventing. Until enough events exist the band is `UNKNOWN` and the generic boundary
applies. **Layer 1 is what would eventually let dimension C leave `UNKNOWN` — on evidence, not on a
model's recollection of which universities run pre-reads.** Not implemented.

# 10. Operator presentation (design only)

Three independent rows. Never collapsed into one verdict.

```
ACADEMICS                                          ⓘ what Thriv3 checks

  Admissions      Pre-read recommended before relying on this
                  Enrolled students average 1553; this athlete's 1250 is
                  ~300 below, at a university admitting 5%.

  Eligibility     Not checked
                  Thriv3 does not yet check NCAA or NAIA academic eligibility.

  Process         Unknown
                  No academic-process evidence on file for this programme.
```

**Four rules the layout enforces:**

1. **"Not checked" is a first-class value and reads differently from "Clear".** Dimension B must say
   it was not checked, not stay silent, or the operator will read the row as a pass.
2. **Every row states what is unknown**, not only what is known.
3. **The process row is never a colour or a severity.** It is informational, and phrased as a
   property of the institution.
4. **Absence of an admissions warning is never rendered as "academically cleared."** The required
   wording carried from A7.30 sits next to the block: *Thriv3 checks institutional admissions
   evidence only. It does not check NCAA or NAIA initial eligibility.*

# 11. Explanation contract

Every academic output carries four parts, in this order:

| part | dimension A example |
|---|---|
| **WHAT WE KNOW** | Enrolled students average 1553 on the SAT; this athlete's 1250 is about 300 points below. The university admits roughly 5% of applicants. |
| **WHAT IT MEANS** | This may be an academic reach. Recruited athletes are assessed differently and how much latitude this institution gives is not known to Thriv3. |
| **WHAT TO DO** | Confirm academic admissibility with the coach, or request a pre-read, before relying on this programme. |
| **WHAT WE DON'T KNOW** | Thriv3 holds no coach-supported admissions decision for this programme, no testing policy, and does not check NCAA or NAIA academic eligibility. |

The fourth part is **mandatory and may not be empty**. A missing "what we don't know" is how a
bounded signal gets read as a complete one — the failure A7.30 found.
