## §F majorFit authority — **the finding**

majorFit is the largest Opportunity component when it applies: weight 1.2
against Playing Pathway's 0.65, taking a **0.545 share**.

Answering the brief's question directly: **no weakly recruitable programme
jumps into an elite position.** Every Top-25 entrant under a declared major
sits at Recruitability percentile 45–96% (absolute R 0.555–0.866). The gates
still constrain. That half of the test passes.

The problem is on the other side.

**`notable_majors` is a share-thresholded subset, not a catalogue.** It is
derived from College Scorecard PCIP completion shares and names a mean of
**7.55 of 14** families — Chicago lists 5, MIT 4, Carleton 6. Absence from the
list is evidence that a family is not among an institution's higher-completion
fields. It is not evidence the programme is not offered.

`majorFit` nevertheless returns, for the non-match branch:

```
value: matched ? 1 : 0,
// A named list of families against a matched family. Nothing is inferred.
grade: GRADE.MEASURED,
coverage: 1,
```

The comment is accurate for a match and inaccurate for a non-match. A match is
a measurement; a non-match is an **inference from absence in a partial list**,
graded as a measurement at full coverage. Nothing in the repository
acknowledges the limitation.

The asymmetry makes it sharp: **the same missing knowledge refuses when the
list is empty (`NO_PROGRAMME_MAJOR_EVIDENCE`, 6 cells) and scores a confident
0 when the list is merely short (558 cells).**

Magnitude: a 0→1 swing on a 0.545 share moves Opportunity by ~0.545 and Pursuit
by ~0.16, against a Top25→Top100 band of ~0.07. **The inference outweighs the
entire operational slice.**

Observed consequences for `X-declared-major`:

| | |
|---|---|
| cells given a MEASURED 0 by inference | **558** of 1,229 supported |
| of those, moved down vs the null-major arm | 530 |
| crossing out of Top 25 / 50 / 100 / 250 | **14 / 23 / 41 / 87** |
| downward distance | p50 **62**, p90 **252**, max **355** |

Examples, all at the top of their own Recruitability distribution:

| programme | R | R pct | rank |
|---|---|---|---|
| Rose-Hulman | 0.920 | 99% | #728 |
| Delaware Valley | 0.934 | 99% | #513 |
| Clarkson | 0.871 | 97% | #593 |
| Rhodes College | 0.856 | 95% | #442 |
| University of Chicago | 0.907 | 98% | #14 → **#182** |
| Carleton | 0.865 | 96% | #15 → **#144** |

This is an **evidence-truthfulness** defect — acceptance category 2, "a score
must not assert knowledge Thriv3 does not possess" — not a weighting opinion.
Re-weighting majorFit would move the symptom; the component would still grade
an inference as a measurement.

**Blast radius is small and bounded.** It is reachable only when an athlete
declares a major: all ten A8.0 reference athletes leave `intended_major` null,
so the entire A8.0 baseline is unaffected, and V2 is wired to no route. One
component, one branch, one grade assignment.

## §J Financial authority

No assumed aid. An unanswered contribution refuses with
`NO_FAMILY_CONTRIBUTION` and never scores 0. `NOT_A_CONSTRAINT` resolves to
viability 1 uniformly — the absence of a limit, not an invented budget.
Contribution changes move Financial and downstream Pursuit only, in 0
Recruitability and 0 Opportunity cells. Affordability is not a quality proxy:
for the athlete who can afford everything, Financial carries 92% tie mass and
near-zero ordering information.

**PRODUCT_INTEGRATION_REQUIREMENT:** V2 requires a resolved contribution state
before rankings can be presented. Financial is required in Pursuit, so an
undeclared family gets 0 ranked programmes and 1,422 LIMITED_DATA. Correct
semantics; a product decision, not a scoring one.

## §Q Product integration requirements

1. A resolved contribution state is required before any ranking is presented.
2. Unsupported associations need a truthful UI state — "we hold no eligibility
   rule for this association", never a low score or an omission.
3. LIMITED_DATA must read as "not enough evidence", never "bad match".
4. The full universe is retained; Top 100 is the operational slice, not the model.
5. **New:** adjacent ranks are not defensible differences. The UI should present
   bands, not an implied precision of #100 vs #101.
6. **New:** declaring a major materially reshapes the list. Until the §F repair
   lands, major should not be collected, or its effect must be presented as a
   filter the user can see and undo rather than a silent ranking input.
