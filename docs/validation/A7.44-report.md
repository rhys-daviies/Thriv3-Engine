# A7.44 — programme-level unreadable-position evidence propagation

Implementation `b4a4798`, preregistration `97b4744`, on `feature/matchmaking-v2`.

## The defect

`buildPositionIndex` counted roster rows whose position it could not read, and
then dropped them. Every position bucket at such a programme was built from a
roster with a hole in it, and no bucket was ever told. 1,695 rows across 328 of
2,060 programmes are in that state.

The counter that existed — `bucket.unreadable` — is a different fact. It counts
players we DID place at a position and whose class year we could not read. One
is doubt about WHEN a player leaves; the other about WHETHER they were ever in
this group. They are not addends, and summing them would count twice every row
that is both.

## What changed

| | |
|---|---|
| `positionUnreadable` | a position was recorded and could not be canonicalised |
| `positionMissing` | no position was recorded at all — zero today, counted anyway |
| `classUnreadable` | the pre-existing doubt, now named rather than inferred by subtraction |
| `unreadable` | unchanged: the UNION the diagnostics have always read |

Propagated into both readers of the index — `returningCompetition` on the
returning side, `positionalOpportunity` on the departing side. Both had the
same hole.

**No value moves.** An unplaceable player becomes neither a returner nor an
absentee and is never distributed across the four positions. Grade, coverage
and explanation carry the doubt; `coverage.js` rule 1 keeps it out of the
number. Candidate G is byte-identical (`opportunityRules.js` blob
`6d6c6cd9e7cb071ae6bcdee335492cf0bd19caac`).

**The threshold is borrowed.** `POSITION_READABLE_SHARE_FLOOR` IS A7.37's
`ZERO_CLAIM_READABLE_SHARE`, and a test asserts they are the same number so
neither can be retuned alone.

The asymmetry with A7.37 is deliberate. A7.37's floor governs a ZERO claim
only, because rows whose year we could not read could only ever make a returner
count LARGER — refusing a non-zero count would discard a real observation for
being incomplete in the athlete's favour. Unplaceable players run the other
way: they can only ADD competition, so they undermine the LOW count, and a low
count is exactly what scores as a wide-open position. Here the optimistic
reading is the one that needs the floor.

`NO_READABLE_POSITIONS` is a new refusal because the existing words were untrue.
`NO_ROSTER_ON_FILE` claimed Thriv3 holds no roster for a programme whose roster
it had read; `NO_CLASS_LABELS` blamed the class years of a roster whose class
years may be perfect. Both sent a reader to look for data that is already there.

## Preregistered against actual

Both runs read one frozen 2026 roster snapshot (62,251 rows), at entry year
2027. Cell identity sets are identical; digest in
`A7.44-preregistration.json`, per-cell result in `A7.44-cell-comparison.json`.

### Playing Pathway (`returningCompetition`)

| | preregistered | actual |
|---|---:|---:|
| MEASURED → PARTIAL | 932 | **87** |
| scoreable → UNSCOREABLE | 273 | **270** |
| refusal reason corrected | 107 | **107** |
| numeric change, still-scoreable cells | 0 | **0** |
| unexpected transitions | — | **0** |

**Why 273 became 270.** Three cells were already refusing `NO_CLASS_LABELS`
before A7.44. The simulation did not model A7.37's class guards and counted
them as scoreable; they never were. No cell refused that was not preregistered.

**Why 932 became 87.** The simulation assumed every scoreable cell was
MEASURED. Of the 932: 844 were already PARTIAL, 87 were genuinely MEASURED and
fell, 1 was already refusing. The evidence effect still lands on the
already-PARTIAL cells — through coverage, which grade could no longer express:
**741 cells lose coverage while keeping their grade.** The remaining 190 had
coverage exactly 0 already, so multiplying by the positional share left 0.

### Coach Recruitability (`positionalOpportunity`)

Not preregistered — the preflight measured only the pathway side — and repaired
because §C names both and the hole was identical.

| | actual |
|---|---:|
| MEASURED → PARTIAL | 738 |
| scoreable → UNSCOREABLE | 260 |
| refusal reason corrected (`NO_CLASS_LABELS` → `NO_READABLE_POSITIONS`) | 106 |
| numeric change, still-scoreable cells | **0** |

More cells fall in grade here because this layer's grade does not already carry
A7.37's horizon-depth penalty, so many more were still MEASURED to lose.

- total Top 100 membership swaps: **22**

- **movement from a cause other than an A7.44 refusal: 0**

All 219 changed programme-cells were checked against the preregistration by
name and position. Every one is a preregistered `SCOREABLE_TO_UNSCOREABLE`
cell. No `MEASURED_TO_PARTIAL` cell moved a ranking, which is the design.

**Why the movement is larger than "270 cells refuse" suggests.** When
`returningCompetition` refuses, `playingPathway` does not refuse with it — it
falls back to rotation-only at coverage 0.4, pre-existing A7.37 behaviour. So
the programme keeps a score and it is a different score, built on the half that
survived. That is the refusal propagating, not a value A7.44 adjusted; the
cell-level measurement above confirms zero still-scoreable cells changed value.
Goalkeeper is the most affected because the groups are smallest: the same
handful of unplaceable players is a majority of a goalkeeper group and a
minority of a midfield one.
