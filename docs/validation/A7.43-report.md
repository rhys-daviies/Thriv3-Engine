## 1. Pipeline root cause — two independent defects, not one

**A. The opaque-id assumption is in TWO synthesisers, not one.** A7.42 named `variants.py`;
`browse.py` builds the same `/roster/season/{YEAR}` form. Both treated a calendar year as a season
**identifier**, and Kansas State proved the segment is opaque — its canonical reads `season/1536`
for a 2016 roster.

**B. `season_ok` could not reject a distant year.** Its rejection window ran `season−2 … season+3`,
so `"2016 Men's Track & Field"` returned **`None` — "cannot tell"** rather than `False`. That is why
Kansas State's page survived the existing season check.

So the two contaminated programmes slipped through for **different reasons**:

| | why it passed |
|---|---|
| Grand Canyon | season was genuinely 2026; **no sport check existed anywhere** |
| Kansas State | season was 2016, but outside `season_ok`'s window → `None` → no rejection |

**C. No sport check existed at all,** and `parse_nuxt` scans the whole payload — 5,028 entries at
Grand Canyon — with no scoping to the requested team.

## 3. Source-resolution change

`/roster/season/{YEAR}` is **no longer synthesised blind**. It is offered only when the *source URL
already spells a season that way* — then the form is the site's own convention rather than our
guess. Applied identically in `variants.ladder` and `browse.season_urls`.

**No institution-specific hack.** The general rule replaces the general assumption; Grand Canyon and
Kansas State are not named anywhere in the fix.

## 4. Identity contract

Ported, not redesigned. `assess(html | signals, requested_sport, requested_season)` inspects
`<title>`, `rel=canonical`, `og:url`, the payload `displayTitle` and any explicit sport slug, and
returns **`sport` and `season` independently**, each `AGREES` / `CONTRADICTS` / `UNKNOWN`, plus an
action.

## 5–7. Sport, season and UNKNOWN behaviour

| | rule |
|---|---|
| **sport** | names a foreign sport → **CONTRADICTS** (even alongside the wanted word — a combined athletics page mentions both, and the safe reading of an ambiguous page is not "yes"); names the wanted sport → AGREES; **names neither → UNKNOWN** |
| **season** | read only from human-readable text, **never from a URL** — the `/season/NNNN` segment is not a year. Any explicit other year → CONTRADICTS |
| **action** | either CONTRADICTS → **REFUSE**; sport UNKNOWN → **REVIEW**; else EXTRACT |

### The spec was corrected during the port, on evidence

My first port followed the JS exactly: a page naming *neither* sport read as `CONTRADICTS`. Measured
against **all 2,060 real 2026 acquisitions**, that would have refused **8 legitimate pages** whose
titles are simply silent about the sport — *"Pomona Pitzer Athletics"*, *"Long Island University
Athletics"*, *"2026 Kangaroos"*, and one carrying a typo, *"Men's **Socccer**"*.

**Silence is not contradiction.** Both contaminated pages named a foreign sport, so the harm is
caught by the first branch; the third branch would only have cost working acquisitions — exactly the
damage §8 warns against. `shared/sportIdentity.js` was corrected to match, so the spec and the port
do not drift.

**Precedence:** an explicit contradiction on either axis refuses outright. UNKNOWN never certifies —
it is returned as its own verdict and recorded — but it does not block, because a page that says
nothing has not told us we are wrong.

### `season_ok` widening, with measured blast radius

The window now spans `1990 … season+2`. Against the same 2,060 real titles it rejects **exactly
one — Kansas State's "2016 Men's Track & Field"** — with 2,053 still `True` and 6 `None`. **Zero
false rejections.**

## 8. Extraction-order proof

`lib.parse_roster()` is now the only authorised reader. On `REFUSE` it returns `(None, title, None,
ident)` **without calling `parse_any`**. The suite proves it by monkey-patching `lib.parse_any` with
a counter:

```
PASS  REFUSE returns no records
PASS  REFUSE returns no parser
PASS  parse_any was NEVER invoked          (calls = 0)
PASS  parse_any IS invoked once identity agrees   (calls = 1)
```

This is identity **authorising** extraction, not extraction followed by a late rejection. All five
call sites are wired, including `browse.extract`, whose **`EXTRA_JS` DOM scrape is gated too** — that
path is `dom-card`, which produced Utah State's and George Mason's rows and has no idea what team it
is reading.

argument for a page-level check.
