# A7.34 — NCAA ID public export safety fix

**Narrow product-integrity patch.** No matchmaking, scoring, eligibility-rule or database change.
Production matchmaking scoring remains `0ae0399`.

---

# 1. Root cause

`server/export/renderProfile.js` renders the **public athlete profile** — the page exported and sent
to college coaches. Its own docstring: *"Anyone holding the link sees the page, so nothing goes on it
beyond what the representation agreement covers."*

Two defects, both from the same mistake — **treating the presence of a value as a statement about
it**:

```js
// line 101 — the verification claim
if (present(athlete.ncaa_eligibility_id)) items.push('<span class="badge">NCAA ID verified</span>');

// line 203 — the identifier itself, in the public Academic record card
row('NCAA Eligibility ID', athlete.ncaa_eligibility_id),
```

The value is free text typed by the athlete (`src/components/PublicProfileFields.jsx:66`, a plain
`<Input>` with placeholder `2110042886`). Thriv3 performs **no format validation, no checksum, no
NCAA lookup, no Eligibility Center certification check**. A single keystroke earned the badge — and
a test in §7 confirms it did.

# 4. Public behaviour BEFORE

- Badge row: `Committed · Class of 2027 · ` **`NCAA ID verified`** ` · New Zealand` — whenever the
  field was non-empty, whatever it contained.
- Academic record card: `GPA · SAT · ACT · ` **`NCAA Eligibility ID: 2110042886`** ` · Intended major`.

# 5. Public behaviour AFTER

- Badge row: `Committed · Class of 2027 · New Zealand`. **No NCAA badge exists at all**, for any
  value.
- Academic record card: `GPA · SAT · ACT · Intended major`. **The identifier is not published.**

Both removals carry a comment in the source. The badge comment names the four replacements that
would be equally unsupported — *"NCAA verified", "eligibility verified", "NCAA registered" and
"eligibility confirmed"* — so a future reader reintroducing one has to do it against an explicit
instruction.

**The academics card itself is unchanged**, and a test asserts GPA and SAT still publish: a
regression that silently dropped the whole card would otherwise pass every other assertion here.

# 6. Internal behaviour

**Unchanged, deliberately.** The column, the intake field and the operator workspace row all remain.
Stored values are untouched — no historical value is deleted and `renderProfile` is proven not to
mutate the athlete it is handed.

**What presence of the field now means, and only this: *an identifier was supplied*.** Not verified,
not eligible, not certified, not registered.

**Legitimate operational purpose:** it is the handle a *future* official-status workflow would use —
the key to the only body that can answer the eligibility question (A7.32: the NCAA Eligibility
Center). That is worth keeping internally. It is not worth publishing.

**Data minimisation, stated narrowly and without legal claims:** this is a third-party identifier
tied to a minor's academic record; public disclosure is unnecessary for coach evaluation, because a
coach assesses the athlete and the Eligibility Center is the party that looks the number up.
Minimisation therefore favours keeping it internal.

interesting case, and is excluded from the containment assertion, with the reason in a comment.
